# V0.7 Architecture

Codex Desktop is the Agent/orchestrator. Career Ops is an upstream source of job-search workflows, Germany/DACH policy, evaluation/tailoring rules, and mature provider implementations. Our thin integration layer normalizes upstream candidates at the `NormalizedJob` ingestion boundary and keeps upstream code unmodified.

SQLite remains the only canonical operational state. This application owns deterministic permanent Job IDs, deduplication, canonical source and source ownership, review/application state, audit history, migrations, the private candidate profile, and the existing Next.js Dashboard/backend shell. Schema changes are additive and migration-safe.

The ingestion flows are:

- LinkedIn discovery → normalization → `NormalizedJob` → our `ingest()` → SQLite.
- Career Ops providers → normalization → `NormalizedJob` → our `ingest()` → SQLite.
- Career Ops/Codex tailoring → structured factual CV material → RenderCV → generated artifact.

RenderCV owns rendering only; it does not own job state or feed job ingestion. The separate pinned LinkedIn specialist is an optional best-effort, public unauthenticated, low-volume personal-use discovery source. Its CLI owns LinkedIn search and detail parsing; this repository owns preference filtering, normalization, and SQLite state.

| Area | Owner |
| --- | --- |
| Agent/orchestration | Codex Desktop |
| Workflow, policy, provider capability | Career Ops upstream |
| Normalization, identity, state, audit, UI/backend | This repository / SQLite |
| CV rendering (planned) | RenderCV |
| LinkedIn discovery (optional) | Pinned LinkedIn specialist |

## Non-goals

- No LangGraph, CrewAI, AutoGen, second agent runtime, second canonical tracker/database, cloud/auth/SaaS requirement, or automatic final submission.
- No direct modifications to upstream Career Ops.
- No Career Ops `applications.md`, `pipeline.md`, `scan-history.tsv`, reports, or database as operational state.
