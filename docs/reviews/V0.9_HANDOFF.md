## Architecture and runtime

- Electron owns the native window, workspace selection, local server process, navigation boundary, and app lifecycle. The existing Next.js app remains the application and SQLite remains canonical state.
- Electron packaging is isolated in `desktop/`; root scripts are `npm run desktop:dev` and `npm run desktop:package`.
- The selected workspace path is stored by itself under Electron `userData`. The native folder picker validates the project name, app directory, installed Next.js runtime, standalone server, production build, and static assets.
- The app launches `.next/standalone/server.js` from the selected workspace using Node resolved through a macOS login shell. It prepares the existing `.next/static` and optional `public` assets in the standalone output, binds to an available `127.0.0.1` port, waits up to 45 seconds for a response, and opens the local URL in one hardened BrowserWindow.
- Internal URLs stay in Electron. External links open with the system default browser. There is no preload bridge; Node integration is off and context isolation is on.
- A single-instance lock is requested. A second LaunchServices invocation activates the app, restores a minimized window, and focuses it. Explicit Quit sends SIGTERM to the backend and escalates to SIGKILL after five seconds.
