## Delivered scope

- Added a narrow public Personio adapter for explicitly configured sources only. It requires an explicit HTTPS public career-site URL such as `https://company.jobs.personio.de`; bare tenant names are rejected rather than guessed. It normalizes jobs into the existing discovery/ingest path, uses `personio:<tenant>:<job-id>` identities, records source tenants, isolates provider and malformed-source failures from other configured providers, accepts supported public `<tenant>.jobs.personio.<tld>` forms, skips malformed position records, and keeps normalized job URLs on the configured Personio source.
- Personio discovery now uses the documented public Company Career Site XML feed at `/xml?language=<lang>`, not the unsupported JSON path. XML positions are deterministically normalized from public `id`, `name`, `office`, `jobDescriptions`, and `employmentType` fields.
- Hardened Germany-focused structured-location filtering without an observed-country blacklist. It retains Germany, explicit EU/Europe/worldwide eligibility, and mixed or ambiguous locations; it rejects clear foreign-local city/country locations, country-only structured locations, explicit incompatible regions, and slash/or combinations whose every location is clearly foreign. The small fixed alias set recognizes the common structured country abbreviations `US`, `UK`, and `GB`; it is not general global country support. It also recognizes explicit `legally authorized` and `unrestricted work authorization` foreign requirements. It does not infer visas, citizenship, legal eligibility, or a country-by-country work-authorisation policy.
- Made role-family matching title-led. Description-only generic management or operations terms no longer qualify unrelated roles; clear title matches, punctuation/plural variants, and plausible adjacent titles remain available for Review.

No database migration, review-gate change, scoring redesign, material-generation change, browser automation, runtime LLM, or additional ATS support was added.

## Real local production trial

- Ran discovery against the user's existing private source configuration using only a disposable `/private/tmp` database and storage root; no production job data or materials were altered.
- The normal private-preference run attempted three configured public sources and completed with no provider failures, but produced no Review candidates under the user's role filters.
- A second run using the same source configuration with a disposable Germany-only, no-role-family preference profile captured two new jobs with unique external IDs and `PENDING` Review state. The captures were from the existing Greenhouse and Lever paths; no configured Personio job was captured in this sample.
- Repeating that second run against the same disposable database produced two duplicates and no new jobs, confirming real rediscovery/deduplication behavior.
- A final bounded public Greenhouse `figma` trial used a disposable Germany-only, no-role-family configuration. It completed with no provider failures and retained one `Berlin, Germany` job in `PENDING` Review state. Before the final structured-country fix, the same source had retained a `Singapore` location; the final run no longer admitted it. The disposable artifacts were removed after inspection.
- The sample is evidence that configured discovery and the Review boundary remain operational. It is not evidence for a new provider, matching, scoring, CV, or application-automation batch. Personio's live configured source returned no captured sample in this run, so non-empty real-world Personio response compatibility remains covered by deterministic tests rather than this limited trial.
- Verified locally: the documented XML endpoint implementation, realistic XML response-shape tests, deterministic normalization, stable external IDs, same-tenant URLs, provider failure isolation, and deduplication. Not fully live-verified: repeated public tenant XML attempts returned HTTP 429 in this execution environment. Live non-empty Personio validation blocked by remote rate limiting in this execution environment.

## Known limitations and deferrals

- Personio support is limited to explicitly configured public HTTPS `*.jobs.personio.*` career-site URLs; there is no bare-tenant inference, tenant discovery, generic employer crawling, or additional ATS framework.
- Geography checks deliberately recognize clear structured geography only. They are not immigration advice and do not infer citizenship, visa status, or work-authorisation rules.
- Role relevance remains deterministic lexical matching. Broad standalone `management` is intentionally not a qualifying family; standalone `operations` requires a senior operations title. No embeddings, ML, or LLM classification is used.
- The externally supplied `V0.5_ROADMAP.md` and `POST_V0.4_ROADMAP.md` were reviewed after implementation. The V0.5 roadmap confirms the delivered scope; the post-V0.4 roadmap remains a deferred decision framework. The production trial did not demonstrate the evidence threshold for any post-V0.5 batch.
