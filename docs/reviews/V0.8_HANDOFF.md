## Status

Focused C2C findings were repaired and revalidated. v0.8 remains pending external re-review; this branch has not been merged, tagged, pushed, or released.

- Released baseline: `v0.7.2`, `main`, `498161e5bb5cecb45cf6c0d8c7159383287e0da9`.

- Scope: presentation-only Dashboard and Job Detail workflow redesign; no database, provider, discovery, canonical-analysis, materials, application, export, or integration behavior change.

## Delivered scope

- Replaced the marketing-style landing hierarchy with a five-stage operations workflow: Discover, Review, Analyze, Materials, Apply.
- Added actionable queue summaries, compact job items, explanatory empty states, and an explicit valid `0 new` discovery result.
- Centralized user-facing next-step projection for Review, insufficient-source Blocked, Codex Desktop analysis, materials/retry, manual application, active tracking, and history.
- Added a clipboard-only `Copy Codex prompt` action using the exact job prompt. It does not call Codex or mutate state.
- Centered Job Detail on a dominant Next Step panel and explicitly states that applications are submitted manually on employer sites.
- Kept canonical 1–5 evaluation display and existing endpoints/actions intact. No dependencies were added.

## Validation and verification

- `npm run verify:core`: passed — 15 files, 131 tests.
- `npm run verify`: passed — 19 files, 188 tests; typecheck, lint, and production build passed.
- Browser inspection used an isolated temporary SQLite store, then removed it. It verified a successful `0 new` summary, a completed-with-issues run, and distinct Analyze, Materials, and Ready to Apply detail states without touching production data.
- Production build retained existing non-fatal dynamic-filesystem tracing warnings; this change did not introduce them.

## Independent review

Independent review identified three presentation-layer correctness findings:

- Discovery `checked` incorrectly used accepted/jobs-seen data and converted missing diagnostics into zero-like display values.
- Zero-new runs with failures were described as normal completion.
- Dashboard used a score-shaped JSON check instead of the existing usable canonical-analysis boundary, allowing Dashboard and Job Detail projections to disagree.

The focused repair uses `filtered_candidates + accepted_candidates` only when both modern diagnostics are present, otherwise keeps an honest legacy `new / duplicates` summary. It projects completed-with-issues runs separately, and Dashboard now passes the existing `readUsableJobAnalysis()` decision into the shared queue/next-step projection. A material-ready legacy record retains its existing secondary manual-status control, while an unusable analysis remains primarily in Analyze.

Fresh external re-review is still required; this handoff does not mark v0.8 PASS or CLOSED.
