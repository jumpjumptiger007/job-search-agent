## Delivered scope

- Added the thin repository-local [job-agent Skill](../../.agents/skills/job-agent/SKILL.md). It routes Codex Desktop through a permanent Job ID, canonical SQLite JD, private factual profile, read-only Career Ops policy, and project validation/persistence boundary. It neither creates nor uses Career Ops operational state.
- Added the project-owned `JobAnalysis` contract in `lib/agent-workflow.ts`, stored in the existing `jobs.analysis_json` column. No migration was needed.
- Added typed factual-profile loading/validation. Candidate-facing evidence is represented only as validated references to profile skills, experience entries/bullets, summary, education, or languages. A matching analysis must declare those approved references, and `unsupportedClaims` must be empty.
- The contract validates factual JD evidence for requirements, keywords, seniority/work-model/location interpretation, and Germany/DACH considerations. The latter supports only evidenced language, employment, work model/location, probation/notice, collective-agreement, 13th-salary, VWL, bAV, and document-expectation topics.
- Added input build, validation, read, SQLite persistence, and `AGENT_ANALYSIS_PERSISTED` audit functions. Unknown IDs, insufficient source content, bad schema/job ID, unsupported facts, unproven JD evidence, and non-1–5 scores fail before any write.
- The new 1–5 `analysis_json.evaluation.score` is authoritative. Legacy `jobs.score` remains untouched for existing dashboard/export consumers; no fake 1–5-to-100 conversion was introduced.
- Discovery now stops at filtering, ingest/canonicalize, and Review. It no longer loads a profile/scoring configuration or writes deterministic scores. `lib/scoring.ts`, `lib/relevance.ts`, automatic score hooks, and their active tests were removed.
- Materials now require a persisted valid analysis and consume its reference-only tailoring plan. DOCX/PDF rendering is unchanged and remains the temporary Gate 6 compatibility layer. A missing evaluation returns a clean 409 instead of marking material generation as failed.
- A substantive JD upgrade invalidates prior `analysis_json` so an analysis cannot survive changed source content.

## Policy and safety boundary

- No production SQLite, profile/CV, historical jobs, or generated materials were changed. Gate tests use and clean isolated `/private/tmp` data.
