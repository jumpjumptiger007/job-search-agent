## Factual YAML and artifacts

`buildRenderCVDocument()` accepts the factual profile and validated `JobAnalysis` read through the existing Gate 4 workflow. It maps profile name/location/email/phone directly when present; includes the factual summary unchanged; maps only `tailoringPlan.skillIndexes` to Skills; maps only selected experience entries and bullet indexes to Experience; and retains factual education strings as text entries. Free-form experience dates use RenderCV's display `date`; education strings are not parsed into degree, institution, or year fields. JD keywords are not injected as candidate claims.

The project persists generated `resume/rendercv.yaml` with a fixed v2.8 schema reference and RenderCV's generated `resume/resume.pdf`. Both are artifacts, not state. The active resume DOCX and custom resume PDF paths are removed; historical files are not deleted or advertised. The existing cover-letter DOCX/PDF renderer remains, and the package PDF combines the RenderCV resume PDF with the cover-letter PDF. SQLite remains the only canonical operational state. There is no runtime LLM inside Next.js.

Generation still requires an existing substantive job marked `INTERESTED`, a current validated analysis, and valid tailoring references to the current factual profile. Source upgrades that clear `analysis_json` block generation. RenderCV runs in a temporary folder; its PDF must exist, be nontrivial, load through `pdf-lib`, and contain a page before the YAML/PDF are staged into canonical paths. A renderer failure records `MATERIAL_GENERATION_ERROR`, sets material status `ERROR`, and records no `MATERIAL_GENERATED` success. Review and application states never advance automatically.
