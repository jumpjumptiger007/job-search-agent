## Baseline and implementation

- Implementation branch: `codex/v0.7-gate-8`.
- Implementation commit: `e4396a6` (`feat(v0.7): redesign dashboard workflow`).

Gate 8 redesigns the server-rendered local Dashboard and job workspace only. It preserves SQLite ownership, the existing POST routes, discovery/evaluation/material behavior, and human-controlled application status.

## Delivered UX

- `/` presents the primary `Search → Review → Tailor → Apply` workflow, with compact recent discovery activity, Review/Tailor/Apply queues, and supporting Active applications and History views.
- Tailor keeps `INTERESTED` jobs with `content_status=INSUFFICIENT` visible as `Blocked: insufficient source`; it also identifies missing analysis and material-generation errors.
- Apply represents material-ready and ready-to-apply jobs while retaining the explicit manual application-state control.
- Dashboard and job-detail scores use only `analysis_json.evaluation.score` in the 1–5 model. Missing or malformed data renders as `Not analyzed`; legacy `jobs.score` and `score_explanation` are not presented.
- Dashboard CSV/XLSX exports now use `Evaluation Score (1–5)` from the same canonical helper.
- `/jobs/[id]` shows permanent ID, core facts, workflow/review/material/application states, official source, existing actions, generated artifacts, structured stored analysis, and collapsed captured source information. It explicitly states that no UI action submits an application.
- Desktop uses dense table-like rows; below 800px these become labeled, readable card rows without the old 850px horizontal-table constraint.
