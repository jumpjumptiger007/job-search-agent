# V0.1 Handoff

This is a local-only, single-user personal job-search automation tool. It is not an autonomous AI agent. Keep changes practical and small (YAGNI): avoid unnecessary SaaS complexity, authentication, cloud infrastructure, multi-user permissions, review bureaucracy, runtime LLM dependencies, and speculative abstractions.

Codex or Claude Code may be used externally to maintain the repository, run commands, inspect results, and implement changes. The application itself must remain independently runnable as deterministic local software.

The workflow is discover → deduplicate/canonicalize → score → tailor materials → human applies → track status. Candidate facts must never be fabricated, and applications must never be auto-submitted.

## Delivered implementation

The local-first Next.js dashboard now starts on Next.js 16.3.4 with exactly pinned React 19.2.0 and TypeScript 5.9.3 dependencies. The prior build/start failure came from a corrupted dependency lockfile that had installed TypeScript 7 despite the declared TypeScript 5 constraint. Rebuilding `node_modules` and the lockfile from the exact pins resolved it.

The application provides SQLite-backed permanent IDs, source retention, Greenhouse and Lever adapters, official-source canonicalization, deterministic duplicate handling, captured JDs, audit events, dashboard/detail views, and CSV/XLSX export. Greenhouse extraction now decodes entity-escaped descriptions before preserving the original captured text.

Material generation is implemented in `lib/materials.ts`. It only runs when the ignored private `profile/profile.yaml` has a factual `name`; otherwise it records an error rather than inventing candidate information. It produces selectable-text ATS-safe DOCX/PDF resume and cover letter files plus a combined PDF package, runs lightweight file QA, retains generation audit history, and keeps material approval/application states separate.

## Known limitations

- Discovery is limited to explicitly configured public adapters; there is no broad web-search layer.
- Turbopack reports non-failing warnings that dynamic local job-folder paths cause broad output tracing. This is intentional for the local filesystem storage design and does not affect the successful build or local use.
- The v0.1 document generator uses the factual YAML profile directly. Deterministic JD-aware selection/reordering and ATS-specific style variants remain future extensions; it does not fabricate facts or submit applications.

## Next major capability

The next major capability is deterministic JD-based resume tailoring: use the captured JD to select, prioritize, and reorder factual profile content while keeping final review with the user. No runtime LLM is required.
