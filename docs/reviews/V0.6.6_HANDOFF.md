## Delivered scope

- Detects only the confirmed corruption pattern: a URL owner differs from the external-ID match, the external-ID match already stores that URL as its canonical URL, and incoming company/title/location matches the target.

## Root cause and recovery

The observed runtime state had `JOB-0005` owning the HELU KABEL URL while `JOB-0008` retained that URL as `canonical_url` without a source row. Rediscovery resolved the URL owner first, so the stronger external ID for `JOB-0008` was never considered; `INSERT OR IGNORE` then preserved the wrong ownership.

The v0.6.6 rule does not let external IDs override URL identity globally. It repairs only when the persisted canonical URL, external ID, and company/title/location independently agree on the other permanent job. The source move, canonical updates, audit event, and related consistency updates share one transaction. A successful repair always restores the former owner's canonical URL/source from an actual remaining persisted source row, including when its prior canonical fields were stale.

Final review found and this branch fixes a blocker in the initial repair: the former-owner safety check was tied to whether that job's stored canonical URL was the moved URL. A stale canonical URL could therefore leave the owner with no source rows after moving its only actual source. The final implementation checks for any other persisted source row before moving ownership; if none exists, it throws `SOURCE_OWNERSHIP_REPAIR_UNSAFE` before mutating the transaction.
