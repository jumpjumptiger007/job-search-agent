## Delivered scope

- Preserves normal URL-first identity for consistent persisted source ownership.
- Detects only the confirmed corruption pattern: a URL owner differs from the external-ID match, the external-ID match already stores that URL as its canonical URL, and incoming company/title/location matches the target.
- Moves only the conflicting `job_sources` row inside one SQLite transaction, restores the target canonical source, preserves permanent job IDs, and leaves unrelated source history intact.
- Keeps the former owner rather than deleting it; when its canonical source would have no replacement, the repair fails and rolls back.
- Adds focused regressions for historical repair, URL-first identity, external-ID fallback, company/title/location fallback, identical-JD separation, initial-source rollback, and repair-failure atomicity.

## Root cause and recovery

The observed runtime state had `JOB-0005` owning the HELU KABEL URL while `JOB-0008` retained that URL as `canonical_url` without a source row. Rediscovery resolved the URL owner first, so the stronger external ID for `JOB-0008` was never considered; `INSERT OR IGNORE` then preserved the wrong ownership.

The v0.6.6 rule does not let external IDs override URL identity globally. It repairs only when the persisted canonical URL, external ID, and company/title/location independently agree on the other permanent job. The source move, canonical updates, audit event, and related consistency updates share one transaction.
