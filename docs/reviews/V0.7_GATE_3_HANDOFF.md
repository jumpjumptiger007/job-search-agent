## Greenhouse mapping

- Existing config remains `type: greenhouse`, `board`, optional `limit`.
- Integration entry: `{ name: board, api: "https://boards-api.greenhouse.io/v1/boards/<board>/jobs" }`.
- `sourceName` and `ats`: `Greenhouse`.
- `externalId`: `greenhouse:<board>:<job-id>` only when the configured board and numeric job ID are proven from the returned Greenhouse URL; otherwise absent.
- The deliberate upstream date supersession is `first_published` rather than legacy `updated_at`; focused coverage records this change.
- The provider output passes through `adaptCareerOpsJob()` and then the unchanged `matchesPreferences()` / `ingest()` path. Career Ops state is not created or used.

## Lever mapping

- Existing config remains `type: lever`, `company`, optional `limit`.
- Integration entry: `{ name: company, api: "https://api.lever.co/v0/postings/<company>" }`.
- `sourceName` and `ats`: `Lever`; `discoveredVia`: `configured ATS`.
- The pinned provider remains the sole fetch/parser. Its injected transport is wrapped once to observe the returned JSON; there is no second request or legacy HTTP path.
- After exact `hostedUrl` correlation, raw `additionalPlain` is appended to Career Ops’ description using the legacy newline semantics, raw `workplaceType` becomes `workModel`, and a non-empty raw string ID becomes `lever:<company>:<id>`.
- Ambiguous or absent raw URL correlation supplies none of those compatibility fields or external IDs.
- Deliberate upstream supersessions retained: Career Ops combines `categories.location` with `categories.allLocations`, and maps raw `createdAt` to `postedAt`; legacy Lever kept only the primary location and had no posted date. Focused coverage asserts both outcomes.

## Personio mapping

- Existing config remains `type: personio`, explicit HTTPS `source`, optional `company`, `language`, and `limit`.
- Sources are fail-closed to explicit `<tenant>.jobs.personio.de` or `.com` hosts. The host validates before discovery, while the pinned provider remains the only fetch/parser.
- `sourceName` and `ats` are `Personio`; `discoveredVia` is `configured ATS`; `externalId` is `personio:<tenant>:<numeric-id>` only when the provider's canonical job URL proves both values.
- A transport wrapper observes the one XML response already fetched by Career Ops. It extracts `jobDescriptions` and `employmentType` only for a numeric ID returned by the provider; it never creates jobs from the observed response. Final description drives `contentStatus` through `adaptCareerOpsJob()`.
- Deliberate upstream supersessions: Career Ops combines the primary `<office>` with `additionalOffices`; maps XML `createdAt` to `postedAt`; and falls back from XML 404 to the tenant HTML page in English. The old host kept only the primary office, omitted `postedAt`, and failed on XML errors.
- XML requests no longer carry the legacy `language` query (the pinned XML provider has no language setting; its HTML fallback requests English), and non-numeric fixture IDs are rejected. `language` remains accepted in configuration so existing files do not fail validation.
- The compatibility observer is tested against nested descriptions containing literal `</position>` text. It ranges only between successive opening `<position>` tags and still enriches only IDs already accepted by the pinned provider.
